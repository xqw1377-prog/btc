## 1. 一句话

AURORA 是单品种 **BTC/USDT 永续** 的资金操作系统：感知市场 → 大脑决定仓位 → 风控改写或拒绝 → 内核在交易所下开仓单并挂保护腿。

它不是多品种交易终端，不是回测平台，也不是已经放行的实盘产品。

## 3. 产品做什么 / 不做什么

### 做

- 每 30 秒拉 1 分钟 K 线，只用**已收盘**棒计算特征和信号
- 四个信号（趋势 / 突破 / 动量 / 均值回归）加权后给出 OPEN / HOLD / CLOSE
- 风控可以否决开仓，并覆盖止盈止损百分比
- 开仓走市价；成交后强制挂止损，尽量挂止盈
- 止损挂失败：紧急平仓并熔断，不允许裸仓
- 止盈挂失败：仓位可继续，标记「有止损、止盈不全」
- 账户指纹锁：同一账户不能跑两个交易进程
- 持仓模式只读核对（默认声明 HEDGE），进程不改账户模式
- 查不到仓位当成 UNKNOWN，禁止当空仓再开

### 不做

- 不自动改杠杆、不自动改 Hedge / One-way
- 不管理多币种、不网格、不定投
- 不保证盈利；没有独立回测成绩作为产品承诺
- 不把旧前端看板当作交易真源（旧 `ws_server.py` 已退役）
- 不在 PAPER 模式出网或下单
- 不在未武装时碰主网

## 5. 主循环（产品路径）

```text
Binance 1m K 线 ×120
    → FeatureEngine（丢掉未收盘棒）
    → 市场状态 TREND / RANGE / TRANSITION（先确认 3 次）
    → 四个 Signal
    → PortfolioBrainV2（再要求状态稳定 3 轮，算方向和仓位）
    → RiskGate（可 HOLD，并覆盖 SL/TP）
    → 若开关打开：ArmedRuntime / Orchestrator
         市价开仓 → 强制 STOP_MARKET → 可选 TAKE_PROFIT_MARKET
```

开仓门槛（当前参数，不是「已经验证能赚钱」）：

- 市场状态连续稳定 ≥ 3 轮（约 90 秒，且外层状态机也有 3 次确认）
- 加权净分 \|score\| ≥ **0.25**，平均置信度 ≥ **0.30**
- 风控未熔断、未超日亏 / 回撤 / 连亏、风险分 < 0.75

2026-09-07 测试网日志：先 `Regime not stable (1/3)(2/3)`，随后分数 0.137 / −0.080，全部 HOLD。这是门槛高于信号，不是通道坏了。

平仓来源：

- 交易所止损 / 止盈成交
- 反向信号票权 > 70% 时大脑发 CLOSE
- 软件里「价格碰到内存止损止盈」——同步仓位后可能失效（见第 8 节）

代码里的 `exit = 0.10` **没有接到平仓**。

## 6. 资金怎么用（产品合同）

以 2026-09-07 测试网为例：可用余额约 **5000 USDT**，BTC 约 **79680**。

| 规则 | 代码真实行为 | 审核时注意 |
|---|---|---|
| 资本口径 | 启动时读一次 `availableBalance` | 不是权益；持仓后不自动重读 |
| 下单数量 | `round(资本 × 仓位比 / 现价, 3)` | **不乘杠杆** |
| 仓位比 | 大脑 3%–40% → 风控截断 → 目标层再乘 → 夹到 **2%–35%** | 没有 10 笔收益时目标乘数固定 0.4 |
| 最小数量 | < 0.001 BTC 则不开 | 5000U 按 2% 刚好约 0.001 BTC（约 80U 名义） |
| 杠杆 | 代码不设置、不检查 | `.env MAX_LEVERAGE=5` 和风控字段 `max_leverage=3` 都是死配置；实际看币安账户 |
| 日亏 / 回撤 | 内核默认日亏 **3%**、回撤 **8%** | `.env` 的 5% / 10% **没接到** |
| 同时持仓 | 只许一方向一笔 | HEDGE 双腿都有仓 → UNKNOWN，禁开 |

名义仓位 ≈ 可用余额 × 仓位比，不是「账户权益 × 杠杆 × 仓位比」。  
若币安账户杠杆不是 1x，交易所侧保证金占用会和产品文档的「仓位比」对不齐。

## 7. 止盈止损（产品合同）

有三套数字，**只有第三套上交易所**。

| 层 | 止损 | 止盈 | 是否上交易所 |
|---|---|---|---|
| 大脑 ATR | TREND 2×ATR / RANGE 1× / TRANSITION 1.5×，再除以价格 | TREND 3× / RANGE 1.5× / TRANSITION 2× | 否，下一行覆盖 |
| 风控百分比 | TREND 2% / RANGE 1% / TRANSITION 1.5%，再乘波动与连亏 | TREND 4% / RANGE 1.5% / TRANSITION 2.5%，再乘波动与置信度 | 是，变成绝对价 |
| 内核保护腿 | `STOP_MARKET` reduceOnly，**强制** | `TAKE_PROFIT_MARKET`，**可选** | 这是唯一真实保护 |

补充：

- 浮盈 > 1% 时，大脑把内存止损收到开仓价 ±0.5%，**不会改交易所止损单**
- 从交易所同步仓位时，内存 SL/TP 被写成 0：多头会立刻像「止盈」、空头会立刻像「止损」。重启后账户里还有仓，有误平风险
- 波动率用的是 1 分钟收益 × √(24×365)，却当单笔分数去放宽止损，单位混用

按当前盘口粗算（TRANSITION、尚未开仓）：止损大约 1.6%，止盈大约 2.6%。5000U 若只开 0.001 BTC，这一档止损大约亏 13 USDT，不是账户的 1.6%。

## 8. 安全边界（产品承诺）

这些是产品对资金的硬承诺，审核时应当当作「做不到就停」：

1. 默认 PAPER；LIVE 未武装时，在构造任何主网 Client 之前拒绝。
2. TESTNET 只允许 `testnet.binancefuture.com` / `testnet.binance.vision`。
3. 缺密钥、指纹不对、模式冲突、探活失败 → 拒启，不静默回落主网。
4. 查不到仓 = UNKNOWN ≠ 空仓。
5. 止损腿失败 → 紧急平 + kill，不留裸仓。
6. 提交结果不明（SUBMIT_UNKNOWN）禁止自动重提。
7. Kill 时仍允许紧急平仓，不得封死 `close_position`。
8. 单账户单实例。

LIVE 武装令牌：`AURORA_ARM_LIVE=I_ARM_LIVE_EXECUTION`。双重授权单独不够。  
**当前产品决定：不接主网。**

## 11. 已知产品缺口（审核清单）

请逐条标：接受 / 必须先修 / 以后再说。

1. **没有独立回测**，不能把「会开仓」说成「会赚钱」。
2. **三套止盈止损**，文档若只写 ATR 就是在说谎。
3. **杠杆和 `.env` 日亏/回撤是死配置**，操作者会误以为已经生效。
4. **资本只读一次 availableBalance**，和「按权益管理资金」的产品叙述不符。
5. **重启带仓可能误平**（同步 SL/TP=0）。
6. **移动止损是假的**（只改内存）。
7. **TESTNET 连续运行、断线注入、人工对账、密钥轮换证明**都还没有，所以主网仍 NO-GO。
8. `execution_truth.py` 冻结，未接生产；P0-B3 官方 SDK 未做。
9. 旧 README 仍写 `portfolio_brain_v3` / `execution_engine_v2`，那些不是当前产品。
